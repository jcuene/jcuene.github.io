I'm getting into development more and more, and it has become a genuinely fun new hobby for me. A lot of that momentum has come from AI tools like Claude, which helped make coding feel approachable instead of intimidating. Now I'm adding [Codex](https://openai.com/codex) to that workflow, starting with this blog.

One reason I've added Codex is simple: I want a smoother path from idea to finished result. I don't just want help thinking through what to build. I also want help turning those ideas into actual files, changes, commits, and published work. For a project like this blog, that feels especially useful because it makes the process feel lighter and more repeatable.

What I like already is that Codex feels built for doing the work, not just discussing it. That doesn't replace the value of Claude for me at all. If anything, it gives me another tool for a different part of the process.

The biggest difference, at least from my perspective so far, is that Claude often feels like a strong thought partner, while Codex feels more like a hands-on implementation partner. Claude is great when I want to reason through an idea, explore options, or shape what I want to say. Codex feels especially helpful when I want to move from plan to execution inside an actual project.

That difference matters because both parts of the workflow are important. Sometimes I want to talk through an idea until it clicks. Other times I want to say, "Let's make this real," and keep moving. Having both available makes the whole process more enjoyable.

I'm still early in learning how I want to use Codex, but that's part of the fun. Every new tool changes the way I think about what is possible, and right now this feels like one of those moments. If Codex helps me write, ship, and experiment more often, it will already be a valuable addition to my workflow.
